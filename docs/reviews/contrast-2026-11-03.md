# Contrast review: all 7 palettes, light and dark (2026-11-03)

Reviewer: qa-accessibility-tester. Standard: WCAG 2.2 AA, 1.4.3 Contrast (Minimum) and 1.4.11 Non-text Contrast.
Source of truth: the color tokens at the top of `app.css` (Green defaults plus the Blue, Red, Orange, Purple, Teal and Monochrome blocks), and the two tokens proposed in `docs/design/settings-options.md` (`--err-ink`, `--line-strong`).

## How this was checked

- `node tests/contrast-check.mjs` reads the tokens straight from `app.css`, resolves the cascade for each palette and mode (palette blocks override Green; `--err-bg` is only defined in the Green blocks, so every palette inherits it), and computes WCAG relative-luminance ratios for every color pair the stylesheet draws. No dependencies. It exits 1 while any current pair fails. `--md` prints the tables in the appendix.
- Blends are computed the way the browser does them in sRGB: `color-mix()` rules (tab bar, soon-row tint, file-drop border, chart tooltip) and `opacity` on text (pump readout labels).
- Thresholds: 4.5:1 for normal text; 3:1 for large text (24 px, or 18.66 px bold) and for UI boundaries, focus rings, state fills and meaningful graphics. WCAG does not round: 4.499 fails.
- The script also checks that each palette's system-dark block and its picked-dark block are identical (they are).
- Not covered: text on photos or icons, the Settings mockups' own CSS (only the tokens they propose), and focus-ring visibility against the selected-tab fill (accent on accent). Contrast in forced-colors / high-contrast mode was not tested.

## Findings

### 1. Blocker: delete button text unreadable in dark mode (all palettes)

- **Where:** `.save.danger { background: var(--err); color: #fff; }`, used by the confirm dialog for "Delete" (vehicle) and "Delete and replace" (CSV Replace import), and planned for Delete all data.
- **Steps:** set Theme to Dark (any palette). Open a vehicle with records, tap Delete vehicle. Look at the red "Delete" button.
- **Expected:** label at least 3:1 (it is 19 px bold, so large text) and ideally 4.5:1.
- **Actual:** 2.21-2.28:1 in all 7 dark themes (white on `#ff8a80`, `#ff85b8`, `#ff8f84`). Light mode passes (6.5-7.4).
- **Fix:** the designer's `--err-ink` works unchanged in every palette, so no per-palette values are needed: `--err-ink: #ffffff` in light, `#1a0b0a` in dark (8.39-8.68:1 on `--err` in all 7 dark themes, 6.54-7.38 in light). Then `.save.danger { color: var(--err-ink); }`.

### 2. Major: control borders below 3:1 (all palettes, both modes)

- **Where:** `border: 1px solid var(--line)` on `select`, text/number/date inputs, `textarea`, `.btn2` (secondary buttons), `.msel`. The input fill is the same `--surface` as the card behind it, so the border is the only thing that shows where the field is.
- **Steps:** open Log, Add fill-up, in any palette and mode. Try to see the edges of the odometer and gallons fields.
- **Expected:** 3:1 against the adjacent color (1.4.11).
- **Actual:** 1.28-1.39:1 in all 14 themes.
- **Fix:** add `--line-strong` for control borders and switch tracks; keep `--line` for dividers, card edges and list rules (those are decorative and need no ratio). The designer's Green values (`#7a867c` light, `#6f7f72` dark) pass in every palette (3.74-4.48), so they would work as-is. They are a green-gray, though, so they read slightly off on Red, Purple and Orange. Proposed per-palette values, each the palette's own `--muted` blended toward `--surface` until it keeps at least 3.4:1 on both surface and bg:

| Palette | Light `--line-strong` | on surface / bg | Dark `--line-strong` | on surface / bg |
|---|---|---|---|---|
| Green | `#7a867c` (designer's; keep) | 3.80 / 3.43 | `#6f7f72` (designer's; keep) | 3.93 / 4.40 |
| Blue | `#7a858f` | 3.76 / 3.44 | `#697580` | 3.46 / 3.90 |
| Red | `#858180` | 3.85 / 3.48 | `#746f6c` | 3.46 / 3.80 |
| Orange | `#878179` | 3.80 / 3.48 | `#777067` | 3.47 / 3.83 |
| Purple | `#818296` | 3.77 / 3.41 | `#6d6e86` | 3.45 / 3.82 |
| Teal | `#748886` | 3.74 / 3.41 | `#607672` | 3.42 / 3.83 |
| Monochrome | `#838383` | 3.79 / 3.45 | `#727272` | 3.47 / 3.89 |

  The dark values sit closer to the line than the designer's Green dark one; if the designer wants Green's margin, lighten each by a step and re-run the script.

### 3. Major: backup-reminder dot nearly invisible in light mode, and has no text

- **Where:** `.tabbar .dot { background: var(--display-fg); }` on `#backupDot` in the Settings tab (index.html line 315). It is shown when a backup is due.
- **Steps:** Light theme, Monochrome palette, with a backup due. Look at the Settings tab in the bottom bar.
- **Expected:** the dot at 3:1 against the tab bar, and the same information available to screen readers.
- **Actual:** 1.11 (Mono), 1.39 (Green), 1.43 (Teal), 1.49 (Purple), 1.74 (Blue), 1.97 (Orange) in light. Dark passes (Red light passes at 4.0). Separately, the `<i>` has no text, so a screen reader announces only "Settings" (1.1.1, outside this contrast pass but found here).
- **Fix:** use `--err` for the dot, as the Settings mockups already do: 6.48-7.77:1 in all 14 themes, no new token needed. Add visually hidden text in the link, e.g. ", backup due". `--display-fg` stays for the pump readout, where it is fine.

### 4. Major (Red) / Minor (Orange): pump readout labels too faint

- **Where:** `.display span:nth-child(odd) { opacity: .65; font-size: 12px; }` (the small uppercase labels in the pump readout).
- **Steps:** Red palette, either mode; open Log and look at the readout labels.
- **Expected:** 4.5:1 (12 px normal text).
- **Actual:** 3.16 Red light, 3.25 Red dark, 4.35 Orange light. All other themes pass (4.58-7.57).
- **Fix:** raise the label opacity to `.85` (smallest value that passes in all 14 themes), or drop the opacity and give the labels a `--display-fg`-tinted token per palette. Red's `--display-fg` at full strength is 5.96 / 6.46, so the token itself is fine.

### 5. Minor: `--ok` on `--ok-bg` just under 4.5 in light mode

- **Where:** `.done-mark` today (the check icon, which is decorative and `aria-hidden`, so the 3:1 graphic rule applies and it passes). It matters once ok-on-ok-bg is used for text, e.g. "Done" status in the Pantry, as the designer's table assumes.
- **Actual:** 4.33-4.40 in Blue, Red, Orange, Purple, Teal, Mono light; Green is 4.4988 (shown as 4.50 in the designer's table, but that fails, since WCAG does not round).
- **Fix:** slightly darker light-mode `--ok`: Green `#1e7858` (4.62), Blue / Red / Teal / Mono `#2c784c` (4.65), Orange `#3b7648` (4.63), Purple `#2c785b` (4.63). Dark mode needs no change.

### 6. Minor: file-drop border on the import button

- **Where:** `.filebtn { border: 2px dashed color-mix(in srgb, var(--accent) 55%, var(--line)); }`.
- **Actual:** 2.95 Green, 2.72 Teal, 2.71 Orange (light). The accent label text inside passes, so the control is still identifiable; ranked minor.
- **Fix:** mix with `--line-strong` instead of `--line` (passes everywhere at the current 55%), or raise accent to 65% with `--line`.

### 7. Minor: chart tooltip "running" text

- **Where:** `.chart .tip .run { color: color-mix(in srgb, var(--run) 55%, var(--bg)); }` on the `--ink` tooltip, 12 px.
- **Actual:** 4.45 Green dark, 4.33 Orange dark.
- **Fix:** 50% instead of 55% passes in all 14 themes (lowest 4.86).

### 8. Note: wizard step bar

`.steps li` (unfilled) is `--line` on surface, 1.28-1.39. The bar is `aria-hidden` and each step says "Step 1 of 3" in text, so progress isn't carried by the bar alone; not a 1.4.11 failure. If the designer wants the bar itself readable, use `--line-strong` for unfilled segments.

## Proposed token changes, in one place

For the frontend-engineer once the owner approves (no app code changed in this review):

```css
/* light, every palette */           --err-ink: #ffffff;
/* dark, every palette */            --err-ink: #1a0b0a;
/* --line-strong: per-palette table in finding 2 */
/* light --ok: per-palette values in finding 5 */
.save.danger      { color: var(--err-ink); }
input, select, textarea, .btn2, .msel { border-color: var(--line-strong); }
.tabbar .dot      { background: var(--err); }               /* plus hidden text ", backup due" */
.display span:nth-child(odd) { opacity: .85; }
.filebtn          { border-color: color-mix(in srgb, var(--accent) 55%, var(--line-strong)); }
.chart .tip .run  { color: color-mix(in srgb, var(--run) 50%, var(--bg)); }
```

After the change, `node tests/contrast-check.mjs` should be updated to read `--err-ink` and `--line-strong` from app.css instead of its built-in `PROPOSED` values, and should then report 0 failures apart from the step-bar note.
